# Каталог продукции — 9833018.ru

Интерактивный каталог продукции в стиле Pinterest / Яндекс с masonry-сеткой, двухуровневым поиском и модальными окнами. Без перезагрузки страницы.

## 📋 Описание

Веб-приложение для отображения каталога продукции сайта [9833018.ru](https://9833018.ru/) в виде адаптивной masonry-сетки (плитки разной высоты). Данные загружаются из `catalog.json`, сформированного Node.js-парсером.

### Основной функционал

| Функция　　　　　　　　　　| Описание                                                                                                                         |
| ----------------------------| ----------------------------------------------------------------------------------------------------------------------------------|
| 🔍 **Двухуровневый поиск** | Ищет по категориям и по отдельным товарам внутри. Запрос «гайки» → категория «Гайки», запрос «гост 5915» → конкретный товар      |
| 📐 **Masonry-сетка (JS)**　| Плитки разной высоты (220 / 300 / 400 px), позиционирование через JavaScript — каждая карточка ставится в самую короткую колонку |
| 🖱️ **Модальные окна**　　　| Клик по категории → модалка раздела с товарами → клик по товару → детальная карточка. Без перехода по URL                        |
| 🏷️ **Быстрые теги**　　　　| Теги под строкой поиска для мгновенной фильтрации                                                                                |
| ⌨️ **Горячие клавиши**　　　| `/` — фокус на поиск, `Esc` — закрыть модалку                                                                                    |
| 📱 **Адаптивность**　　　　| 1–4 колонки, мобильные модалки                                                                                                   |
| 🧹 **Очистка данных**　　　| Автоматическая очистка мусора от парсера (`\n`, `\t`, «Подробнее»», склеенные слова)                                             |
| 🖥️ **SSR**　　　　　　　　 | Серверный рендеринг + серверный API через Nitro                                                                                  |

## 🚀 Быстрый старт

### 1. Установка

```bash
git clone https://github.com/YOUR_USERNAME/catalog-app.git
cd catalog-app
npm install
```

### 2. Генерация типов (обязательно!)

```bash
npx nuxt prepare
```

> Без этого шага IDE будет показывать ошибки: «не удается найти `ref`», «не удается найти модуль `~/types/catalog`» и т.д. Это нормальное поведение Nuxt — типы генерируются динамически в `.nuxt/`.

### 3. Подключение данных каталога

**Вариант А — Использовать парсер:**

```bash
cd parser
npm install axios cheerio
node parser.js
cp catalog-data.json ../public/catalog.json
cd ..
```

**Вариант Б — Вручную:**

Положите файл `catalog.json` в папку `public/`. Формат описан ниже.

### 4. Запуск

```bash
# Разработка
npm run dev

# Сборка для продакшена (SSR)
npm run build

# Статический сайт (SSG, для GitHub Pages)
npx nuxt generate

# Предпросмотр собранного проекта
npm run preview
```

## 🔑 Ключевые архитектурные решения

### Почему `shared/` а не `app/utils/`

Папки `app/` и `server/` — это **разные сборки** (Vite и Nitro). Сервер не может импортировать из `app/` через `~/`. Папка `shared/` доступна обоим:

| Алиас | Куда указывает | Доступен в |
|-------|---------------|------------|
| `~/` | `app/` | Только клиент |
| `~~/` | Корень проекта | И клиент, и сервер |
| `#imports` | Авто-импорты Nuxt | Только клиент |

В серверном коде используется относительный путь:
```typescript
import { normalizeCatalog } from '../../shared/utils/normalize'
```

В клиентском коде:
```typescript
import type { CatalogCategory } from '~~/shared/types/catalog'
```

### Почему JS masonry, а не CSS columns

| CSS columns | JS masonry (текущий) |
|---|---|
| Элементы идут сверху вниз по колонке | Каждый элемент → в самую короткую колонку |
| Порядок 1,4,7 / 2,5,8 / 3,6,9 | Естественный порядок: 1,2,3,4... |
| Ломается в Tailwind 4 с `@layer` | Не зависит от CSS-фреймворка |
| Нет контроля высоты | Точный контроль: 220/300/400 px |

### Почему двухуровневый поиск

| Запрос | Результат |
|--------|-----------|
| *(пусто)* | Все категории |
| `гайки` | Категория «Гайки» (91 позиция) |
| `гост 5915` | Товар «Гайки ГОСТ 5915-70» с бейджем категории |
| `болт м16` | Конкретные болты из разных категорий |

## 📊 Формат catalog.json

```json
[
  {
    "id": 1,
    "title": "Название раздела",
    "image": "https://example.com/image.jpg",
    "description": "Описание раздела",
    "url": "https://9833018.ru/catalog/section/",
    "tags": ["тег1", "тег2"],
    "items": [
      {
        "id": "1-1",
        "title": "Название товара",
        "image": "https://example.com/product.jpg",
        "description": "Описание товара",
        "url": "https://9833018.ru/catalog/section/product/"
      }
    ]
  }
]
```

### Поддерживаемые алиасы полей

Функция `normalizeCatalog()` в `shared/utils/normalize.ts` гибко обрабатывает JSON с разными именами полей:

| Поле | Альтернативные названия |
|------|------------------------|
| `title` | `name`, `label` |
| `image` | `img`, `photo`, `thumbnail` |
| `description` | `desc`, `text`, `preview` |
| `url` | `link`, `href` |
| `tags` | `keywords` |
| `items` | `products`, `children`, `elements` |

### Обработка отсутствующих полей

- **Нет `image`** → цветной градиент-заглушка с иконкой
- **Нет `description`** → блок описания скрыт
- **Нет `tags`** → теги генерируются автоматически из заголовка
- **Нет `items`** → в модалке сообщение «Товары не загружены»
- **Нет `url`** → ссылка на сайт не показывается

### Очистка мусора от парсера

Данные от парсера могут содержать `\n`, `\t`, «Подробнее»», «Под заказ», склеенные слова типа «ГайкиГОСТ». Функция `normalizeText()` автоматически:

- Удаляет `\n`, `\r`, `\t`
- Удаляет «Подробнее»», «Под заказ», «В наличии»
- Разделяет склеенные слова: `ГайкиГОСТ` → `Гайки ГОСТ`
- Вставляет пробел между буквой и цифрой: `ГОСТ5915` → `ГОСТ 5915`
- Убирает множественные пробелы
